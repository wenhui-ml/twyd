> 生成时间：2026-11-14 17:55（本机 2×24 GB ROCm，单机）
> 用途：把当前全部实验、数据、结论、在跑任务与待验证假设一次性交给外部读者/分析者。

## 0. 一页速览

**任务**：复现并改进 TWYD 论文的 2× 压缩蒸馏（教师 3.2B → 学生 1.6B），目标是在**固定低秩（LRC）前提**下，
尽量逼近教师，并显著优于论文发布的学生模型 `LRC-1.5B-Base`（其训练预算约 10B token）。

**当前最好的配置**（arm `mix9`）：PT 500M token（50% 维基百科+数学 / 50% fineweb-edu 混合语料，
6 层低秩适配、5.11M 可训练）→ SFT 78M token（纯交叉熵、9 层）。
总预算 **578M token = 论文的 1/17**。

| 指标 | 论文学生 | 我方 best (`mix9`) | 差值 | 配对 p |
|---|---:|---:|---:|---:|
| MMLU（14,042 题） | .5006 | **.5065** | +0.58 pt | 4.0e-2 |
| 7 个行为任务（12,144 题） | .6868 | **.6992** | +1.24 pt | 3.8e-8 |
| 池化 8 任务（26,186 题） | .5870 | **.5959** | +0.89 pt | 1.3e-6 |
| Avg8（含 acc_norm） | .6550 | **.6674** | +1.24 | — |
| **距教师（池化）** | 差 8.74 pt | 差 **7.85 pt** | 补上 **10.2%** | — |
| 距教师（MMLU） | 差 12.16 pt | 差 **11.58 pt** | 补上 **4.8%** | — |

**核心结论**：论文的差距主要是**容量/秩**问题，不是训练配方问题；但在固定秩下，
**语料**（而非 token 量、适配器大小、层位置、损失函数）是唯一能动的杠杆，
且知识语料与网页语料的效应**可加**，两者混合可以同时拿到 MMLU 与行为增益。

**正在跑**：`down_proj` 臂（论文 App.B 的完整模块集），35%，PT 预计 11-15 12:15 完成。

## 1. 技术设定（复现所需）

### 1.1 模型
| 角色 | 模型 | 规格 |
|---|---|---|
| 教师 | `Llama-3.2-3B-Instruct` | 3.2B，hidden 3072，28 层，d_ff 8192，head_dim 128 |
| 学生 | `LRC-1.5B-Base`（论文发布）或由教师压缩构建 | **1,606M**，hidden 1536，28 层，d_ff 8192，head_dim 128 |
| 压缩率 | 2× | MLP 用低秩分解（LRC / Train-What-You-Deploy）表达 |

### 1.2 训练方法（CORE-LR）
- 学生的 MLP 以低秩双因子形式部署；训练只更新**部署后仍然存在**的低秩系数
  （`BRANCH=core, K=64, LORA_MODE=core, FACTORIZED=1, FREEZE_COL=true, PERP_BASIS=teacher`）。
- PT 阶段可训练参数 **5.11M**（6 层 × gate/up），SFT 阶段 **11.2M**（9 层）。
- 损失：PT = logit 蒸馏（KL，T=40，权重 1.0）+ NTP；SFT = 纯交叉熵（见 §4 结论 3）。
- 优化：lr 1e-4、cosine、warmup 3%、clip 1.0、AdamW、bf16、grad ckpt、SEQ 2048、
  BS 1 × GAS 32（每步 65,536 token/卡，2 卡 = 131,072 token/步）。

### 1.3 数据
| 用途 | 文件 | 规模 |
|---|---|---|
| PT（网页基线） | `data/fw_score4_1B.jsonl` | 4.89 GB ≈ 1.2B token（fineweb-edu score≥4） |
| PT（知识语料） | `data/pt_knowledge.jsonl` | 1.21 GB ≈ 300M token（70% `wikimedia/wikipedia` + 30% `open-web-math`） |
| PT（混合，**headline**） | `data/pt_mixed.jsonl` | 2.01 GB ≈ 500M token（250M 知识 + 250M 网页，按 2000 行块交错） |
| PT（混合，顺序复现） | `data/pt_mixed_shuf.jsonl` | 同上，全局打乱顺序 |
| SFT | `data/sft_paper8.jsonl` | 0.50 GB ≈ 78M token（论文 8 任务格式） |

**无评测污染**：wikipedia / open-web-math / fineweb 均为原始文本，不含 MMLU/ARC/CSQA 题目。

### 1.4 评测
- `lm-eval-harness`，0-shot，8 任务：ARC-C、ARC-E、BoolQ、CSQA、PIQA、SciQ、WinoG、MMLU，
  n = **26,186**（MMLU 14,042 + 行为 12,144）。
- 指标：任务有 `acc_norm` 用 `acc_norm`，否则 `acc`。
- 统计：**逐题配对 McNemar**（同一模型对同一题目的对/错），另报池化差值 + 95% CI。
- LogiQA 不可用（`datasets>=4` 移除了脚本加载器），故为 8 任务而非论文的 9 任务。

## 3. 已确立的机制结论（按证据强度排序）

### C1（强）**PT 语料决定能力画像；两种语料的效应可加**

同一套配方、同一 5.11M 可训练参数、同一蒸馏目标，**只换 PT 语料**：

| PT 语料 | token | ΔMMLU | Δ行为 |
|---|---:|---:|---:|
| fineweb-edu（网页） | 524M | −0.08 | **+0.91** |
| wikipedia+math（知识） | 300M | **+0.70** | +0.40 |
| 50/50 混合 | 500M | **+0.77** | **+0.73** |
| 朴素可加预测 | — | +0.31 | +0.66 |

行为几乎精确可加；**MMLU 反而超过可加预测（+0.77 vs +0.31）**，说明网页那一半不只是“不干扰”，
还帮助知识迁移。**结论：不存在必须在两者之间取舍的前沿；正确做法是混合。**

### C2（强）**SFT 只有在 PT 没留下余量时才会“吃掉”MMLU**

| SFT 的起点 | SFT 后 MMLU 变化 |
|---|---|
| 原始学生（未 PT） | **−2.25 pt**（p=1.3e-15） |
| 网页 PT 之后 | −0.37 pt（ns） |
| 知识 PT 之后 | −0.01 pt |
| 混合 PT 之后 | −0.18 pt |

→ “SFT 毁知识”不是 SFT 的错，是**学生没有 MMLU 余量**。PT 先把余量造出来，SFT 就吃不掉。

### C3（强）**SFT 阶段做蒸馏是有害的（与论文配方相反）**

`dist9` 把 SFT 损失从纯 CE 换成论文的 `lrc_distill`（KL T=40 权重 1.0 + CE + Eq.7 aux λ=0.2）：
池化 **+0.49 vs +0.89**（头对头 p=.018），行为 **+0.55 vs +1.24**（p=.0016）。

**机制**：KL 在 T=40 下量级约 200，CE 只有约 1.2；`clip=1.0` 后更新方向被“贴住教师的预训练分布”主宰，
而这正是 SFT 要离开的东西。证据：dist9 的 token_acc 在 SFT 中**下降**（.688→.678），纯 CE 稳定。
→ **蒸馏属于 PT（建立能力），SFT 应该用纯 CE（转换行为）。**

### C4（强）**流水线是确定性的；“单 seed”不是本案的软肋，但 p 值不含训练不确定性**

- `SEED` 是空转开关：seed 42 与 43 的两次 PT **逐点相同**（162 个记录点，max |Δacc| = 4e-4）。
  原因：适配器初始化来自教师权重的确定性 SVD、无 dropout、swift 的 shuffle 用内部固定种子。
- 因此换了**数据顺序**（同一批 432k 文档全局打乱）重跑全链：池化 **+0.88 vs +0.89**，
  头对头 **p=0.98**（discordant 921/919，等于抛硬币）。
- **含义**：报告的所有 p 值都是“题目抽样”p 值，对一个可复现到 0.01 pt 的模型；
  训练侧的顺序敏感性已被实测排除。

### C5（中）**除语料外，所有“容量侧”旋钮都无效**

| 旋钮 | 变化幅度 | MMLU 变化 |
|---|---|---|
| PT token | 524M → 2B（4×） | +0.01 pt（ns） |
| 适配器秩 k | 64 → 256（8.8× 参数） | < 0.6 pt |
| 层位置 | 0-2 / 11-13 / 25-27 / 全层 | ≤ 0.65 pt（无一致方向） |
| 教师思维链 SFT 数据 | +52M token | +0.06 pt（ns） |

→ 固定秩下，**堆量堆参数买不到 MMLU**；语料可以。

### C6（中，待补）论文的 Eq.7 隐状态对齐项在**坏初始化上有害**

在 500M PT（起点是随机 slice 初始化）上开 aux：loss **346 vs 200**、grad_norm **38 vs 10**，
即 aux 在和 KL 打架。原因：学生 1536 维与教师 3072 维的残差流尺度不同，未归一化 MSE 量级约 200；
即使换成相对误差 `‖h^S P − h^T‖²/‖h^T‖²`（aux≈11、λ·aux≈2），在坏初始化上仍然过强。
→ aux 只适合“学生已接近教师”的阶段（这也是启动器 guard 的原意，虽然它当时的实现有 bug）。

- 我们的 SFT 一直是纯 CE，论文两个阶段都蒸馏 → **已测，纯 CE 更好**（C3）。

## 5. 方法论与统计（分析时请按这个口径读数字）

1. **所有比较都是逐题配对 McNemar**，同一批 26,186 题，参照固定为 `LRC-1.5B-Base`。
   独立误差棒在这个样本量下分辨不出 0.5 pt 的差异，配对可以。
2. **池化** = 把 57 个 MMLU 子任务与 7 个行为任务的所有题目拉平后统一算正确率，
   与 Avg8（8 个任务正确率取平均）不同——两者在本文中都给出。
3. **多重比较**：本 study 约 40 个臂。Bonferroni 阈值 0.05/40 ≈ **1.25e-3**。
   - 经得起校正的：`mix9` 池化 p=1.3e-6、行为 p=3.8e-8、`mix9shuf` 池化 p=2.2e-6。
   - **经不起的**：`mix9` 的 MMLU p=0.040、`know9` 的 MMLU p=0.016。对外只能说
     “MMLU 不降反升”，不能说“MMLU 显著提升”。
4. **确定性**：见 C4。seed 无效，顺序已复现；也就是说**报告区间只反映题目抽样**。
5. **无污染**：PT/SFT 语料均不含评测题目；评测集未参与任何选择（唯一例外：`mix9` 的语料配比
   是按“MMLU 是知识型”这一先验选的，不是在验证集上调的）。
6. **单机双卡**，无分布式超参搜索；所有臂共用同一套超参（lr/clip/调度/warmup）。

### 7.2 待验证假设（按“每小时信息量”排序）

**H1 — 赢的语料还没饱和（最可能带来量级提升）**
- 依据：网页单语料早已饱和，但混合语料只测到 500M，且收益仍在上升（知识 300M +0.70 → 混合 500M +0.77）
- 预测：混合语料 **1B**（500M 知识 + 500M 网页）→ MMLU ≥ **.515**，池化 ≥ **+1.1 pt**
- 成本 50 h

**H2 — SFT 的“长度 / 学习率”是剩下的行为杠杆（最便宜）**
- 依据：`ptmix500`（不 SFT）MMLU .5083 是所有臂最高；78M 的 SFT 换来 +0.5 行为、代价 0.18 MMLU
- 预测：0.5 epoch SFT → MMLU ~.5075、行为 +0.95，**Avg8 超过 .6674**；1.5 epoch → 行为更高但 MMLU 开始掉
- 成本 **3–10 h / 点**

**H3 — 教科书语料比维基百科更能推 MMLU**
- 依据：MMLU 是考试题；wiki+math 比纯网页多 0.85 pt MMLU，方向是“越像教材越好”；`nampdn-ai/tiny-textbooks` 已验证可加载
- 预测：textbooks + open-web-math（70/30）300M → MMLU **+0.9 ~ +1.1 pt**
- 成本 27 h

**H4 — 混合比例可能存在最优点而非单调**
- 依据：可加性预测 MMLU +0.31，实测 +0.77 → 存在**协同**；若协同为真，50/50 未必最优
- 预测：30/70（知识/网页）在 MMLU 上可能与 70/30 相当或更好
- 成本 27 h/点；这是唯一能画出“语料-能力前沿曲线”的实验

**H5 — 秩分配（等 DP 结果）**
- 依据：`down_proj` 梯度是 gate/up 的 5 倍 → 该模块此前被饿着
- 方案：`rank_map`（代码已实现，从未使用）把固定总秩预算倾斜到 `down_proj` 或特定层
- 成本 27 h

## 9. 已知局限（分析时请把这些当约束条件）

1. **单机、单配置**：所有臂共用一套超参（lr 1e-4 / clip 1.0 / cosine / warmup 3% / T=40 / λ=0.2），
   **没有做超参搜索**。因此“语料有效、容量无效”的结论只在**这套超参**下成立。
   特别是 C5 的“token/k 无效”有可能被“更适合大规模的超参”推翻。
2. **MMLU 的增益弱**：+0.58 pt，p=0.040，**经不起 40 臂的多重比较校正**。
   强结论只有行为（+1.24，p=3.8e-8）与池化（+0.89，p=1.3e-6）。
3. **离教师仍远**：MMLU 差 11.58 pt（补上 4.8%），Avg8 差 4.6 pt。
   本工作是“同样的压缩率下比论文训得更好”，**不是“接近无损压缩”**。
4. **温启动未被修好**：四种构造（坐标切片 / 嵌入 SVD / 读能量 / 激活协方差 PCA）都无法复现论文的
   低秩初始化（最佳 CE 9.36，教师 2.86）。恒等对照（`P=I`，r=3072）能精确复现教师（CE 2.855），
   证明投影代码正确、**问题出在“截断”本身**：top-r 主成分子空间不承载 Llama 的功能。
   本 study 的 PT 是从坏初始化出发“修”回来的（修复后 CE 2.44，**优于**论文发布学生的 3.05）。
5. **评测集有限**：8 个任务、0-shot；无 LogiQA（`datasets>=4` 移除脚本加载器）；
   无生成式指标（只测多选题 loglikelihood）。
6. **`mix9` 的 MMLU 与 `mix9shuf` 差 0.35 pt**（p=.18，不显著），说明 MMLU 对数据顺序的敏感性
   高于行为指标；报告 MMLU 时应给出两个数的范围（.5065 ~ .5099）。
7. **SFT 数据未做配比搜索**（固定用 `sft_paper8.jsonl`），所以“SFT 数据不是瓶颈”这一说法未被检验。

## 10. 如果只让读者做一件事

请判断下面这个论断是否成立、以及最容易被什么反驳：

> 在 2× 压缩（1.6B / 低秩 MLP）且训练预算仅 578M token（论文的 1/17）的条件下，
> **PT 阶段的语料选择（百科+数学 与 网页 混合）是唯一能同时提升 MMLU 与行为指标的杠杆**；
> 容量侧（token 量、适配器秩、层位置、模块集）在固定低秩下对 MMLU 无效；
> 而 SFT 阶段使用论文的蒸馏目标反而使结果变差。

最可能的三类反驳及其所需的实验，已分别列在 §7.2（H1 语料规模、H2 SFT 长度/LR、H5 秩分配）。
